# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run build          # tsc compile to dist/
npm start              # run the full pipeline (requires ANTHROPIC_API_KEY)
npm run validate       # check all artifacts pass problem.md requirements
npm test               # all tests (unit + integration)
npm run test:unit      # unit tests only
npm run test:integration  # e2e test only (no API key needed — uses StubLLMService)
npm run test:watch     # vitest watch mode
npm run typecheck      # type-check without emitting
```

Run a single test file:
```bash
npx vitest run tests/unit/application/TriageTicketsUseCase.test.ts
```

Run a single test by name:
```bash
npx vitest run --reporter=verbose -t "flags a draft that cites a non-existent chunk"
```

## Architecture

Clean Architecture with a strict one-way dependency rule:

```
domain  ←  application  ←  infrastructure
                        ←  interface
```

`domain` imports nothing from this project. `application` imports only from `domain`. `infrastructure` and `interface` import from `application` and `domain`. **Never import upward.**

### Key design decisions that aren't obvious from the code

**Pipeline state machine** — `PipelineState` is a 13-state enum in `src/domain/pipeline/PipelineState.ts`. Every use case calls `assertState(currentState, REQUIRED_STATE)` at entry; if the predecessor hasn't completed, it throws `PipelineStateError`. This is enforced in code, not documentation.

**Controlled vocabularies** — `src/domain/value-objects/` contains six `const`-union types (`TicketCategory`, `UrgencyLevel`, `Sentiment`, `ResolutionMode`, `Queue`, `ActionPriority`). Each exports a `parseX(s)` that throws `VocabularyError` on out-of-vocab input. LLM output always goes through these. Use-cases use `safeParse` wrappers (try/catch) and fall back to hardcoded safe defaults rather than letting a bad LLM response crash the pipeline.

**source_chunk_ids integrity** — Every output entity carries `source_chunk_ids: ChunkId[]`. Hallucinated IDs (not in the retrieval result) are filtered out at each use-case level. `DraftResponsesUseCase` falls back to `allowedChunkIds` when the LLM returns an empty array so grounding validation always has something to check.

**LLM call logging** — `ILLMCallLogger` is constructor-injected into `AnthropicLLMService` and `StubLLMService`. Every `complete()` call appends one record to `artifacts/llm_calls.jsonl` via `JsonlLLMCallLogger`. Tests use `SpyLLMCallLogger` (in-memory).

**Model selection** — `AnthropicLLMService.selectModel()` uses Haiku for `triage` and Sonnet for all other stages. Override via env vars `TRIAGE_MODEL` / `MAIN_MODEL`.

**low_retrieval_confidence flag** — Set by `RetrieveKnowledgeUseCase` when the top BM25 score is below `confidenceThreshold` (default 0.2) or all top-K scores are within `epsilon` (0.05) of each other. Forces `resolution_mode = needs_human_review` in triage and injects a conservative NOTE into the response prompt.

### LLM stages and their prompt builders

| Stage | Use case | Prompt builder | Asserts state |
|---|---|---|---|
| 1 — Triage | `TriageTicketsUseCase` | `buildTriagePrompt` | `RETRIEVAL_COMPLETE` |
| 2 — Response | `DraftResponsesUseCase` | `buildResponsePrompt` | `TRIAGE_COMPLETE` |
| 3 — Action plan | `CreateActionPlanUseCase` | `buildActionPlanPrompt` | `RESPONSE_DRAFTED` |
| 4 — Grounding | `ValidateGroundingUseCase` | `buildGroundingPrompt` | `ACTION_PLAN_CREATED` |

Prompt builders are pure functions — they take domain entities and return a string. Snapshot-tested in `tests/unit/prompts/`.

### Test doubles

`tests/stubs/StubLLMService.ts` — fixtures keyed by `LLMStage`, then optionally by `TicketId`. Falls back to `'{}'` when no fixture matches.

`tests/stubs/SpyLLMCallLogger.ts` — accumulates `LLMCallRecord[]` in memory; use `logger.records` to assert call count and stage.

The integration test (`tests/integration/pipeline.e2e.test.ts`) wires the real `PipelineOrchestrator` with `StubLLMService` against committed `tickets.json` + `knowledge_base/` and writes artifacts to a `tmp` directory.

### Artifacts written to `artifacts/`

`knowledge_corpus.json`, `retrieval_results.json`, `triage.json`, `response_drafts.json`, `action_plan.json`, `grounding_validation.json`, `final_ticket_outputs.json`, `queue_ranking.json`, `audit_log.json`, `llm_calls.jsonl`. The `artifacts/` directory is gitignored and regenerated by `npm start`.

## TypeScript notes

- `strict: true`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` — all enabled.
- Module system is **CommonJS** (`"module": "CommonJS"`). Use `__dirname`, not `import.meta.url`.
- Import paths in source use `.js` extensions (Node16 resolution convention), even though the files are `.ts`.
